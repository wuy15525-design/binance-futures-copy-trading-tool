# 合约跟单台 4.3.17

安装包适用于 Android 13 及以上。使用原发布签名的正式包可以覆盖安装旧版。币安组合页读取、成交存档、策略、委托、持仓核对和通知全部在手机上运行。

安装或更新后，第一次打开显示 3 秒开屏画面。首次查看使用提示时可直接打开免责声明。作者信息和免责声明也可在「设置 → 关于」查看。

## 4.3.17 更新

优化了建档去重逻辑以及读取错误处理，解决了价格约束失效问题。

## 4.3.4 更新

- 建档以首次读到的最新成交为基准，最多读取向前 7 天的历史。跨过边界后，保留边界当秒的全部成交。成交历史不足 7 天时，在核对日期窗口确实读完后即可建档。
- 官网未显示展开按钮时，按需重选日期并核对前后记录是否重合。重选后短暂显示「暂无记录」会等待页面加载并重试一次。若仍不能核对，保留进度，等待补齐。

## 4.3.3 更新

- 网页稳定后才点击「更多」，相邻点击至少间隔 1.2 秒。网页显示暂时繁忙或展开失败时，等提示消失后再等 1.5、3 或 6 秒，按当前页的尝试次数调整，成功展开后恢复正常节奏。
- 自动重试期间，本轮无法补齐时约 8 秒后从已读位置续读。达到无进展上限后，可在运行页点「在应用内展开成交」，在原网页点「更多」，然后点「核对并继续」。

## 4.3.2 更新

- 建档分页暂时停住时，同一次运行中优先保留网页和已核对的记录。下一轮从已读页续读，日期控件可用时再缩短日期窗口。系统回收网页时，从头重新验证。
- 连续三轮没有新增已核对的历史成交时，运行页显示已保留笔数和失败原因，并提供「重试官网读取」。核对到官网末尾且档案连续后才完成建档。

## 4.3.1 更新

- 「添加合约」从币安实盘公开接口读取 USDT 永续合约。首次安装时无需保存账户 API 密钥即可读取。列表包括已上线交易的股票、商品等 TradFi 永续，以及使用中文代码的永续合约。
- 在测试网运行时，仍按测试网实际支持的合约核对。

「合约跟单台（测试版）」可以与正式版同时安装。测试版使用独立的应用包名，白名单、成交档案、运行状态、网页会话和 API 密钥各自保存在本机的应用空间。首次打开测试版时会从默认设置开始。若两版连接同一个币安实盘账户，币安侧的订单和仓位仍属于同一个账户。

## 4.3.0 更新

- 首次建档或补录时，「更多」反复未返回新增成交会保留已读记录，再按交界日缩短结束日期续读。日期控件晚于成交列表加载时，也能继续核对。
- 日期切换后会核对交界日的成交，再合并并确认列表末尾。运行页会显示续读结果或具体卡住的环节。

## 4.2.9 更新

- 官网成交仅显示「做多／做空」时，也可完成首次建档。结合官网已平仓记录的时间、最大持仓量和已平仓量，以及之后连续核对的成交，判断开仓、减仓及平仓。
- 原始买卖方向与成交完整保留。缺少方向证据的历史成交显示「开平待核对」。跟单期间如白名单内新增成交的方向待核对，暂停本轮自动委托，继续核对官网档案。

## 4.2.8 更新

- 首次建档或补齐旧档时，官网「更多」反复未返回新增记录，会从已读成交的最早一天缩短结束日期续读。核对日期和交界成交，确认读到末尾后再完成建档。
- 同秒同价同量的成交使用官网仓位历史复核。开平仓时间、最大持仓量和已平仓量能唯一吻合时，才归并历史基线中的多余副本。原跟单进度及账户成交保留。

## 4.2.5 更新

- 网络恢复、官网成交与账户核对完成后，自动按已保存的复制系数重新计算调仓目标。
- 调仓加仓统一使用复制系数窗口的最大不利价差，调仓减仓继续使用市价单。

## 4.2.4 更新

「检测到的新增操作」从本地成交档案独立分页。已读取到但尚未接上档案的信号会标记「待核对」，补齐后保留首次检测时间。初始基线和历史补录列在成交记录中。

复制调仓按合约并行读取仓位、盘口与杠杆档位。某个合约尚在等待或读取失败时，其他已核对的合约可以继续。委托提交仍须核对账户保证金和在途订单。

## 选择跟单方式

首次开启一轮新的实盘或官网信号测试网跟单时，可选「按点位跟随」或「复制仓位比例」。旧版已运行的跟单按点位恢复。已有未结束的跟单仓位、委托或等待时，继续使用该轮已保存的方式。

「按点位跟随」使用逐合约配置中的定额或定比保证金、杠杆与不利价差规则。「复制仓位比例」以官方成交记录的 USDT 成交额除以对应组合页的「带单保证金余额」，得到这笔操作占余额的倍数。资产管理规模是页面单列的数据项。

选择复制仓位比例时可输入复制系数，默认 1×。每笔带单操作倍数乘以本账户 U 本位 USDT 保证金余额，再乘复制系数，得到本次目标名义金额。0.5× 是原比例的一半，2× 是两倍。开仓和加仓用预设杠杆换算保证金，按交易所支持的实际杠杆和数量精度发单。例如带单成交额 2,000 USDT、保证金余额 1,000 USDT，对应两倍。本账户保证金余额 500 USDT、复制系数 0.5× 时，目标名义金额是 500 USDT，实际使用 5 倍时需要约 100 USDT 保证金及手续费缓冲。

部分减仓也按同一规则换算名义金额，用当前可执行盘口估算市价单数量，上限为本账户对应方向实际仓位。带单员的可见持仓已全部平掉时，本机清空该方向已纳入跟单的仓位。识别到开仓或部分减仓信号但成交额、余额未读到时，App 会等待。带单余额来自公开页面快照，成交时刻的原始余额由交易所掌握。已有仓位补跟以推算数量和开仓均价估算名义金额，再乘复制系数。

「运行 → 自动跟单 → 调整复制系数」可同时修改系数和加仓调仓价差。保存后使用最新有效的官网快照和账户实际持仓计算差额。目标数量等于纳入跟单的带单员剩余数量，乘以本账户和带单员的保证金余额之比，再乘复制系数。实际仓位高于目标时立即尝试市价减仓。实际仓位低于目标时，优先用本账户同方向开仓均价核对不利价差，缺少该字段时可用带单员推算均价。买入按卖一、卖出按买一判断。价格符合时发限价 IOC，超限时继续跟踪价格。

等待加仓时，带单员在同合约同方向加仓或减仓都会更新目标。目标仍高于实际仓位时继续用原调仓参考价和价差检查加仓，只补剩余差额。目标低于实际仓位时以市价减到新目标。带单员清仓时按市价流程清仓。部分成交后先核对原单再续算差额。「等待开仓与调仓」显示目标、参考价和等待状态，并可取消。

改系数可能立即触发市价减仓，按实际成交价结算盈亏，并可能产生滑点。调仓价差只约束加仓。加仓会增加保证金占用和杠杆敞口，成交可能产生手续费。

小额委托按币安对应合约的步长向下取整。低于最小数量或名义金额的开仓、加仓意向或剩余调仓差额，会在下一笔同方向带单成交后重新核算。若只是当前一档盘口量不足，等待盘口恢复。旧版复制账本的系数为 1×，升级后保留跟单进度。旧账本缺少已纳入跟单的带单数量时，首次调仓会用本机实际仓位和双方公开或已核对余额估算原有跟单范围。

## 查阅组合和成交

在「设置」可输入组合 ID、币安官方组合链接，或从「历史带单员」下拉清单选择以前跟过的组合。保存新组合前，App 核对官网详情和带单员名称。官网退回列表、找不到该组合或暂时无法确认时会提示原因并保留原设置。停止运行后切换组合会开始一轮新的跟单，切回旧组合也会重新确认是否补已有仓位。旧组合的成交和账户成交留在各自档案里。

每次有新成交时，按合约和方向更新推算仓位。加仓按成交量加权更新均价。部分减仓维持可见开仓成本，平仓盈亏推得的成本与其有差异时会显示提示。同一轮持仓中，前后两次部分平仓和中间加仓满足推算条件时，可估算超出可见记录的数量和成本，并标注来源。平仓量达到或超过可见数量时结束该方向，后续同方向开仓独立计价。

带单员的「估算强平价」按当前已知仓位和均价估算，开仓、加仓、减仓和平仓记录更新后重新计算。成交档案有缺口时，缺口后可核对顺序的已见记录参与展示估算，自动委托仍依赖连续的成交档案。估算采用 USDT 全仓情景。计算某个合约时固定其他合约参考价，并计入这些合约的维持保证金。同一合约的多空方向共用全仓计算结果。

余额暂缺时沿用同一组合最近记录的官网余额。缺乏余额记录时，以已知持仓开仓名义金额的 1/20 模拟钱包余额。标记价暂缺或与余额快照时间不接近时，以该合约已知持仓加权均价作为参考价。币安档位可用时优先使用，缺档位按 0.5% 维持保证金率，超过可读取档位时按末档延伸。持仓栏标出所用假设以及因缺价暂未计入估算的情况。带单员的私有仓位、逐仓保证金和账户模式可能使实际结果不同。估算强平价用于持仓展示。

「我的当前持仓」按方向显示币安返回的开仓均价、浮动盈亏、持仓保证金和强平价，以及按合约查询的实际杠杆。持仓保证金对应 `positionInitialMargin`，逐仓钱包有余额时另列。币安强平价为零或未返回时，卡片显示「—」。仅监测官网时可同时用已保存的实盘密钥读取持仓，也可在「设置 → 币安 U 本位合约账户」单独查询。

首次跟踪或补录时，从首屏展开到币安当前列表的末尾。确认官网已稳定显示末尾后，按实际读到的页数建档。首次遇到空列表，会刷新组合页再次确认。若旧版曾用空快照覆盖衔接点，升级后会从已有档案找回最后一笔，先逐页核对，再同步仓位。遇到分页请求失败、超时或内容尚未稳定时会退避重试，并在运行页显示具体阶段。

同一秒的成交沿用官网列表顺序。不同秒的记录在页面中交错时，按成交时间从早到晚归并，响应式布局中的重复时间线只读取一次。成交时间、方向、价格和数量都相同的行会独立核对完整一秒，同时比对成交额和盈亏。缺少记录或同秒明细无法对齐时，会保留核对样本并显示「同秒成交待核对」。证实属于重复的明细会从成交列表、CSV 和持仓计算中排除。

日期复核会等待官网控件加载，并可翻月选择默认展示范围以外的可选日期。日期筛选无法完成时，用独立刷新后的官网列表逐页复核。只在读到完整一秒时确认该组成交。

官网显示地区限制或要求确认地区时保留档案，暂停自动委托，每两分钟尝试重新读取。运行页提供「打开币安组合页」和「重试官网读取」。提示在原组合页中时，可以在 App 内查看和操作币安的实际提示，再从同一网页会话重试。官网拒绝访问或跳转到其他页面时，可以用浏览器打开组合页查看原因。安全验证、登录要求或拒绝访问时等待手动重试。抓取恢复后，按档案连续性和实际持仓核对恢复跟单。

日常轮询首屏无法衔接档案末尾时会逐页展开。档案连续性验证通过后读取账户实际仓位，再处理遗漏记录造成的各合约、各方向的净仓位变化。净增加保留对应份额并以当前推算均价检查不利点差，净减少按剩余仓位比例减仓。缺口尚未衔接时暂停自动委托。重启沿用原档案。「成交记录」可切换带单员成交和本机已核对成交并导出带单员 CSV。

切换组合后的新一轮跟单会先展开官网成交列表。官网记录无法接续已归档末尾时，将可确认的新成交接在旧档案之后，作为新一轮的仓位基线。跟单从新基线后开始，基线已有仓位按用户的补仓选择处理。

「成交记录 → 带单员成交」下方的「带单保证金余额历史」只列出币安官网划转记录。运行期间用独立网页每分钟检查，分页或网络未完成时保留已确认的划转，并显示失败阶段。起始时已存在的转账写入档案，跟踪开始后新检测到的转账推送到通知栏，并播放提示音。

带单员持仓卡片用推算数量、开仓均价和币安最新成交价计算估算浮盈亏。行情或均价缺失时显示横线。常规价格、保证金和浮盈亏最多显示两位小数，小额价格按有效数字展示。显示舍入仅用于界面。

「运行」中的持仓、首次补仓预览、等待开仓、新增操作和运行记录都可以在各栏内滚动，每页显示 6 项。「成交记录」每页显示 12 笔。每栏底部可查看总页数并前后翻页。运行时，账户的持仓、浮盈亏和钱包余额分别从币安账户接口查询，目标间隔为 1 秒。各条查询串行运行，超时时跳过相应时点，遇到限流会退避。跟单时长由手机每秒刷新，和官网读取互相独立。「我的当前持仓」显示账户各方向的浮盈亏。概览的总盈亏含本轮已核对的已实现盈亏和纳入跟单的仓位浮盈亏，采用计入手续费和资金费前的口径。仓位对账中会显示已确认的已实现盈亏，手动平仓的成交明细缺失时会标出「部分盈亏待核对」。

在「设置」点「添加合约」，从币安 USDT 永续列表搜索并勾选多个合约。列表读取失败时仍可输入完整合约代码添加。点单个合约的「设置」可单独选择定额或定比保证金，设置杠杆与最大不利价差，再点「保存规则」提交。跟踪中可修改保证金及不利价差，新的保证金用于尚未成交的开仓意向，部分成交的意向沿用剩余预算。已有账户密钥时，修改杠杆预设会检查对应合约的多空仓位和本机待核对委托，确认都已结清方可保存。升级保留原有合约的参数。新添加合约的初始设置为每笔 20 USDT 保证金、5 倍杠杆与 0.3% 最大不利价差。

底部导航可切换运行、成交记录和设置。「跟单概览」的总盈亏和钱包余额默认显示星号，点「显示金额」可在当前界面揭示。「运行」页顶部的「捐赠」可分别复制币安转账 UID 和 BNB Chain USDT 地址。

Android 14 至 17 使用专用类型的用户启动前台服务，兼容 Android 13 的前台服务。默认由应用按 Android 通知音量播放内置提示音，播放出错时尝试系统提示音。自选铃声及静音、振动、勿扰沿用系统设置。「设置 → 后台与通知」显示通知声音、电池优化和限制状态，提供「交易通知声音」和「测试通知与提示音」。断网后暂停发送委托，连接恢复后先核对原委托与官网记录。系统强停后可在「运行」重新启用跟单。

本机成交按一笔委托内的实际成交数量计算加权均价。平仓已实现盈亏来自币安成交明细，手续费和资金费为独立项目。对应官网信号的通知显示带单员成交均价及点差比例，买得更贵或卖得更便宜记为正值。历史缺失的价格或盈亏显示「未提供」。

中断期间若有成交已经滚出官网可读范围，App 会保留已有记录和本轮仍可见的成交，标出历史缺口并暂停发单。官网补页接上后恢复核对。3.0 会迁移可用的旧版快照，并从 3.0 开始完整追加。手动导入和本地回放入口已移除，币安测试网演练入口仍可用。

## 在测试网验收

1. 在币安模拟交易账户创建 U 本位合约测试网的 HMAC API 密钥。在「设置 → 币安 U 本位合约账户」点「保存测试网密钥」，再查询测试网钱包余额。手机本地保存的是 AES-GCM 密文，密钥由 Android Keystore 管理。
2. 在「设置」添加测试合约并保存保证金和杠杆。名单含 BTCUSDT 时内置演练选 BTCUSDT，否则选名单中的第一项。测试环境缺少的合约可换成该环境支持的合约。若页面提示低于最小委托量，按显示的最低保证金调整测试参数。
3. 回「运行」允许通知，点击「测试网自动开平仓演练」。App 用测试网盘口验证不利价差规则，然后生成演练信号，在币安测试网自动提交开仓、核对成交、自动平仓。确认「演练通过」、最后仓位为 0，并在币安测试网的订单历史中核对成交。可展开通知查看均价、平仓盈亏和相对演练参考价的点差。
4. 另一次点击「开始自动抓取」，确认「上次有效抓取」的时间持续更新。按「停止自动运行」后可改选「用官网成交跟单到测试网」，让官网新成交走同一执行器。这个模式和实盘读取同一网页，测试网盘口不同或合约未上线时会显示等待原因。

测试网使用币安官方 `demo-fapi.binance.com`。实盘使用 `fapi.binance.com` 和另一组交易密钥。手动启动实盘时，选择跟单方式后会再次显示「当前为实盘跟单」，确认后才启动。后台服务中断后会尝试恢复原模式。只查看实盘余额和持仓可以使用只读密钥入口。请为 App 的实盘密钥启用 U 本位合约权限并保持提现权限关闭。

## 网页自动抓取

App 在前台服务里复用一个 WebView，按 3 秒时点串行刷新币安组合页，自动进入「最新操作记录」。上一轮超过时点就跳过该时点。只接受本轮新页面中的记录。列表暂为空时，会尝试用网页控件重选一次包含上次成交的日期范围，再按需补页。开始使用时先在「运行」选「开始自动抓取」，看「上次有效抓取」是否更新时间和笔数。「上次取数失败」会显示网页导航、标签打开、日期重选、补页、网络或其他错误。

第一次核对完成的抓取建立基线。官网列表顺序异常、抓取超时或跨页缺口会暂停当轮委托。锁屏后频率受手机系统和网络影响。在系统应用信息中允许自启动，按设备提供的选项放开后台省电限制，并检查锁屏成交通知。

「检测到的新增操作」显示快照逐笔比对后的开仓、加仓、减仓或平仓信号，同时显示带单员成交时间和手机首次读到这笔成交的时间。旧版未记录的检测时间保留为空。「等待开仓」显示对方成交价、实时买一或卖一及不利价差。App 按当前所选交易环境核对可交易的 U 本位合约。未收录、暂停交易或盘口被币安拒绝时，在对应等待项显示合约代码和原因。其余可交易合约继续更新。网页读取中断时仍更新等待标的盘口，发单前需要新的连续官网快照。点「取消这笔等待」只取消该笔的未跟部分。已经发送给交易所的委托会继续核对，已有仓位仍按后续减仓和平仓信号处理。

开仓前检查超时会按笔退避重试。等待栏显示失败环节、时间、次数、最早重试时间，以及官网待核对、暂停开仓或原委托号待核对等状态。盘口仍独立更新。带单员同方向全平后，自动运行记录逐笔列出被取消的等待、原开仓与平仓信号时间，以及该笔等待的上次请求错误。

公开网页整页刷新曾实测 60 轮，44 轮读到记录，16 轮显示空，15 轮在 3 秒内读到记录。测试只覆盖当时的浏览器环境。App 的 3 秒设置是调度目标，跳过的时点不会排队。

## 自动交易行为

- 组合在对应账户和环境首次开启官网信号跟单时，App 在「运行」显示名单内可从官网成交推算的已有仓位。点「选择要补跟的仓位」可按合约与多空方向勾选，或选「仅跟后续成交」。确认前继续归档成交。点位补仓每个所选方向使用一份已配置保证金，以推算开仓均价为参考，沿用开仓价差规则。官网仓位变化时需按最新预览重新确认。已确认的选择和等待记录可在重启后恢复。
- 仅处理白名单内的 USDT 永续合约。定比按当前 USDT 钱包余额计算每笔保证金，定额按设置金额。合约空仓时，App 会按本单名义金额选用不超过预设的最高可用杠杆。有仓位时保留币安实际倍数，按预设与实际倍数较低的一项计算新开仓数量。
- 跟踪期间，App 对比账户仓位变化，把本机委托之外观察到的净变动标为「手动操作」。已纳入跟单的方向以币安当前数量参与后续操作。启动前已有仓位按多空分别保留，直到带单员在该方向出现新增开仓。跟踪中在原本空仓的方向手动建仓，也会纳入跟单。平仓仍需带单员有对应的可见开仓。
- 开多检查卖一价，开空检查买一价。只过滤不利价差，使用 IOC 限价控制可成交价格。价格超限会继续等待，原始信号随带单员对该方向的减仓或平仓调整。首次委托前用保证金预算、实际杠杆和可执行限价计算目标数量。部分成交后按实际成交扣减目标数量和保证金预算。低于最小数量或在剩余预算内已无法达到最小名义金额的尾量会结束，并记录原因。盘口数量暂时不足时继续等待。交易所明确按最低数量或金额拒单后，会重新读取合约规则，并等到可委托量或金额足够再请求。
- 平仓先核对该标的同方向的可见开仓和账户实际持仓。推算仓位为零或账户无对应仓位时跳过发单。点位模式以「带单员本次平仓量 ÷ 平仓前推算持仓量」计算比例，上限为 100%，再乘账户当前同方向实际持仓。复制仓位比例模式对部分减仓使用名义金额换算。带单员平仓量等于或超过推算仓位时，全平该方向。平仓使用市价。
- 每次发送订单前将唯一委托号落盘。响应不明会优先按原委托号核对订单、成交明细和仓位，期间暂停发送新委托。开仓请求失败的原因记录在该笔等待项和自动运行记录。实际确认有成交时发送交易通知和提示音。停止运行保留当前仓位。重启同一模式会先核对任何残留委托。
- 暂停开仓时仍处理有明确信号的平仓。调整不利价差会影响该合约的后续开仓判断。修改名单或组合前应停止。若旧账本仍有跟单仓位或待核对委托，保存时会向原币安账户查询。确认相关合约已空仓且跟单委托已结清后，可保存新规则。原组合的成交档案仍可在切回该组合时查看。

## 构建与检查

使用 JDK 17 或更高版本、Android Studio 或 Gradle 9.5。工程使用 Android Gradle Plugin 9.3.3，compile 和 target SDK 37，最低 Android 13（API 33）。运行 `gradle :app:assembleDebug` 可构建调试包。发布包启用 R8 混淆，并在交易服务启动前核对发布证书。Linux 可设置 `ANDROID_SDK_ROOT` 并运行 `scripts/build_apk.sh`。手动构建可用 `COPY_ANDROID_PLATFORM` 和 `COPY_BUILD_TOOLS` 指定本地 SDK 目录，用 `COPY_R8_JAR` 指定独立 R8。覆盖安装需要原签名私钥，由 `COPY_SIGNING_KEY` 指定。签名校验可通过 `COPY_RELEASE_CERT_SHA256` 或 Gradle 的 `copyReleaseCertSha256` 参数配置。

`scripts/check.sh` 需要 Android API 33 SDK。将 `COPY_TEST_JSON` 指向 `org.json:json:20240303` jar。运行 `node tests/website-capture.test.js` 可检查官网名称、自动选标签、空页重选日期和来源校验。`tests/V3ArchiveTest.java` 用 Robolectric 检查 SQLite 档案、持仓展示、前台服务类型、系统通知、界面边距和捐赠复制。Android 16 和 17 的 Robolectric 测试使用 JDK 21。跟单策略检查使用本地输入和模拟交易所回执。
